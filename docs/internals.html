Belső működés

A nxsc fordító és interpreter belső felépítése, komponensei és az AST csomópontok leírása.

Fordítási pipeline

A Niaxinus kétféle végrehajtási módot támogat:

Interpreter mód (--run)

.nxs forrás → Lexer → Parser → AST → exec_node() → kimenet

Az interpreter közvetlenül az AST-t járja be és hajtja végre. Nincs közbenső C kód. Ez a mód a gyors fejlesztési ciklus és a bash-compat tesztelés alapja.

Compiler mód (natív bináris)

.nxs forrás → Lexer → Parser → AST → Codegen → /tmp/*.c → gcc -O2 → ELF bináris

A codegen C11 forráskódot generál, amelyet gcc fordít le. A thread pool párhuzamosítja a fordítást, ha több forrásmodul van.

Komponensek

src/
├── lexer.c / lexer.h — Tokenizálás; ${}/$() egységes WORD tokenek
├── parser.c / parser.h — Rekurzív leszálló parser; AST építés
├── interp.c / interp.h — AST interpreter; exec_node, builtins, expansion

Interpreter (--run) mód

A --run flag az interp.c-ben lévő exec_node() függvényt hívja az AST gyökerétől. Az interpreter állapotot az InterpState struct tartja:

// InterpState — interpreter állapot
typedef struct {
    InterpVar   vars[256];   // változók tömb
    int         var_count;
    int         last_exit;   // $? értéke
    char       *argv0;       // $0
    char      **posargs;     // $1..$9
    int         posarg_count;
} InterpState;

A változók az exported flag-gel rendelkeznek; ha exportálva vannak, az export_var() hívja a setenv()-t, így az értékük gyermekfolyamatokban is látható.

exec_node() — csomópont-diszpécser

Az exec_node() egy nagy switch a csomópont típusán. Minden ág a csomópont szemantikájának megfelelő C kódot futtat:

static int exec_node(InterpState *s, Node *n) {
    switch (n->kind) {
        case NODE_ASSIGN:   /* set_var() */
        case NODE_CMD:      /* try_builtin() → fork+execvp() */
        case NODE_PIPELINE: /* exec_pipeline() */
        case NODE_REDIR:    /* exec_redir() */
        case NODE_BLOCK:    /* fork() + gyerek blokk + waitpid() */
        // ... többi ág
    }
}

Pipeline végrehajtás

Az exec_pipeline() az N szakaszos pipeline-t egy pipe()+fork()+dup2() lánccal valósítja meg:

  1. Minden szomszédos szakasz-pár között létrehoz egy pipe(fd[2])-t.
  2. Minden szakaszhoz fork(): a gyerek dup2(prev_read, 0) és/vagy dup2(write_end, 1).
  3. A gyerek futtatja a saját csomópontját, majd kilép.
  4. A szülő waitpid()-del vár minden gyerekre; az utolsó kilépési kódját adja vissza.
Legfeljebb 64 pipeline-szakasz támogatott (a globális _pipe_pids[] tömb mérete alapján a codegen-ben).

Átirányítás végrehajtása

Az exec_redir() a POSIX dup2()-t használja az fd-ek átirányításához:

// > fajl: stdout → fajl
int saved = dup(STDOUT_FILENO);
int fd    = open(fajl, O_WRONLY|O_CREAT|O_TRUNC, 0644);
dup2(fd, STDOUT_FILENO);
close(fd);

exec_node(s, inner_cmd);

fflush(NULL);              // ← kritikus: C stdio buffer ürítés
dup2(saved, STDOUT_FILENO);
close(saved);
A fflush(NULL) a visszaállítás előtt kötelező, különben a C stdio buffer az eredeti fd-re kerülne ki.

Subshell végrehajtása

A NODE_BLOCK (subshell) egy fork()-ot végez; a gyerek az InterpState stack-másolatával fut, a szülő waitpid()-del vár. A szülő változói nem módosulnak.

pid_t pid = fork();
if (pid == 0) {
    InterpState child_s = *s;  // másolat
    for (int i = 0; i < n->child_count; i++)
        exec_node(&child_s, n->children[i]);
    exit(child_s.last_exit);
}
waitpid(pid, &wstatus, 0);

Expanzió motor

Az eval_string() feldolgozza a stringeket és kibontja a kifejezéseket:

TokenKezelés
${var}, ${var:-d} stb.expand_brace() → szöveg csere
$varget_var() → értéke, vagy getenv() fallback
$?, $$, $!Speciális változók direkt leolvasása
$(cmd)popen() → stdout capture, trailing newline strip
$(( expr ))Aritmetika kiértékelése
\n, \tEscape szekvencia csere
A lexer gondoskodik arról, hogy ${...} és $(...) egységes WORD tokenként érkezzen a parserhez — ha a {/( előtt $ áll, a lexer a záró }/)-ig olvas.

C kódgenerálás

A codegen.c az AST-ból C11 forráskódot generál. Az emit_c_node() minden csomóponttípushoz más C kódot bocsát ki:

Példa: pipeline codegen kimenet

// cmd1 | cmd2 generált kódja
_nxs_pipeline_begin();
if (_nxs_pipeline_stage(0, 2)) {
    /* cmd1 */
    _nxs_pipeline_child_exit();
}
if (_nxs_pipeline_stage(1, 2)) {
    /* cmd2 */
    _nxs_pipeline_child_exit();
}
_nxs_pipeline_wait();

Példa: átirányítás codegen kimenet

int _nxs_saved_fd = dup(1);
FILE *_nxs_redir_fp = fopen("kimenet.txt", "w");
dup2(fileno(_nxs_redir_fp), 1);
fclose(_nxs_redir_fp);
/* inner cmd */
fflush(NULL);
dup2(_nxs_saved_fd, 1);
close(_nxs_saved_fd);

Emittált runtime helperek

A generált C fájl elejére kerülnek a pipeline runtime segédfüggvények:

FüggvényLeírás
_nxs_pipeline_begin()Globális pipeline állapot inicializálása
_nxs_pipeline_stage(i, total)Fork + dup2; gyerekben 1-et, szülőben 0-t ad vissza
_nxs_pipeline_child_exit()Gyerek kilép a pipeline-ból
_nxs_pipeline_wait()Összes pipeline-gyerekre vár, utolsó exit code-ot adja vissza

A generált C tartalmazza még: #include <unistd.h>, <fcntl.h>, <sys/stat.h>, <sys/wait.h>.

Thread pool

A threadpool.c egy POSIX pthreads-alapú munkás-pool. A fordító indításkor CPU-magok számát detektálja és annyi munkásszálat indít. Ez a jövőbeli párhuzamos modul-fordításhoz és a jelenlegi CPU-teszt párhuzamosításhoz szükséges.

// Munkásszálak száma = online CPU-magok
int nthreads = sysconf(_SC_NPROCESSORS_ONLN);
threadpool_t *pool = threadpool_create(nthreads);

Bash-kompatibilitási teszt harness

A tests/bash-compat/compare.sh minden tesztpárra:

  1. Futtatja a .sh fájlt bash-sal → rögzíti stdout/stderr/exit code
  2. Futtatja a .nxs fájlt nxsc --run-nal → rögzíti stdout/stderr/exit code
  3. Összehasonlítja a két kimenetet; eltérés esetén FAIL, egyezés esetén PASS
make test-bash-compat
# PASS control-flow
# PASS extern
# PASS hello
# PASS pipe
# PASS redir
# PASS expansion
# PASS builtins
# PASS cmdsub
# 8/8 tesztek sikerültek
